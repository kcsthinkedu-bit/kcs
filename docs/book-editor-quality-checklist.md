# KCS 책 만들기 품질검사 기준

## 목적

코드가 존재하는 상태, 브라우저에서 동작하는 상태, PDF가 정확한 상태, 실제 종이에 정확하게 인쇄되는 상태를 서로 구분합니다.

검사 결과에는 반드시 검사 날짜, 검사자, 브라우저, 기기, 프린터, 용지, PDF 뷰어와 실제 측정값을 함께 기록합니다.

## 완료 상태 구분

| 상태 | 의미 |
| --- | --- |
| 코드 구현 | 파일과 기능 코드가 존재함 |
| 브라우저 확인 | 실제 버튼과 입력으로 동작을 확인함 |
| 저장 확인 | 저장 성공 응답 후 다시 불러와 같은 내용임을 확인함 |
| PDF 확인 | 외부 PDF 뷰어에서 크기·순서·여백을 확인함 |
| 실물 인쇄 확인 | 실제 프린터와 종이에서 앞뒤 위치·접지·재단을 측정함 |

한 단계의 결과로 다른 단계까지 완료되었다고 표시하지 않습니다.

## 1. 책 만들기 첫 화면

- 데스크톱과 모바일에서 컬러링북·그림책 선택 버튼이 첫 화면 안에 보이는지 확인합니다.
- `사용 안내`, `컬러링북 시작하기`, `그림책 시작하기`가 올바른 경로로 이동하는지 확인합니다.
- 준비되지 않은 회원·수업 기능이 실제 사용 가능한 것처럼 보이지 않는지 확인합니다.
- 키보드의 Tab 키만으로 모든 주요 링크에 이동할 수 있는지 확인합니다.
- 아이콘 없이 글자만 읽어도 버튼 뜻을 알 수 있는지 확인합니다.

## 2. 편집 기능

검사할 동작:

- 앞표지·본문·뒤표지 선택
- 페이지 추가·복제·앞으로·뒤로·삭제
- 앞표지와 뒤표지 삭제 방지
- 글 넣기·그림 넣기
- 마우스와 터치로 글·그림 이동
- 슬라이더로 위치와 크기 변경
- 글꼴·크기·굵게·기울임·밑줄·색상·정렬
- 페이지 바탕색 변경
- JSON 받기와 다시 불러오기
- 이전 `kcs-book-v1` JSON 변환

통과 기준:

- 화면에서 변경한 결과가 편집 화면, 책으로 보기, 인쇄 미리보기에 동일하게 나타납니다.
- 요소가 페이지 밖으로 완전히 사라지지 않습니다.
- 삭제 전에는 확인 문구가 나타납니다.
- 한글을 조합하는 중 글자가 끊기거나 중복되지 않습니다.
- 파일을 다시 불러온 뒤 페이지 순서와 서식이 같습니다.

## 3. 저장과 저장본

검사 흐름:

1. 책을 편집하고 자동 임시 저장 표시를 확인합니다.
2. 브라우저를 닫았다가 다시 열어 현재 작업을 확인합니다.
3. 학생 제출본을 만듭니다.
4. 학생 제출본에서 선생님 수정을 시작합니다.
5. 선생님 수정본을 저장합니다.
6. 학생 제출본을 다시 열어 내용이 바뀌지 않았는지 확인합니다.
7. 최종본을 만들고 각 저장본의 날짜와 종류를 확인합니다.

통과 기준:

- 제출본과 수정본의 ID가 서로 다릅니다.
- 선생님 수정본에는 학생 제출본의 ID가 부모 저장본으로 기록됩니다.
- 학생 제출본은 선생님 수정 이후에도 같은 JSON을 유지합니다.
- 저장 성공 후 저장소에서 다시 읽은 내용이 화면 내용과 같습니다.
- 저장 실패 시 성공 문구가 표시되지 않습니다.

현재 IndexedDB와 localStorage는 로컬 기능 확인용입니다. 서버 권위 저장 검사는 인증·서버 저장 연결 후 별도로 수행합니다.

## 4. 플립북과 페이지 순서

- 앞표지는 한 장으로 표시합니다.
- 왼쪽·오른쪽 본문 페이지가 올바른 짝인지 확인합니다.
- 빈 페이지와 뒤표지가 읽는 순서에 포함되는지 확인합니다.
- 페이지를 이동한 후 플립북 순서가 즉시 바뀌는지 확인합니다.
- 모바일에서는 두 페이지가 너무 작으면 한 페이지 보기로 전환하는지 확인합니다.
- 100페이지에서도 현재 펼침 전환이 지연되지 않는지 확인합니다.

논리 페이지 순서와 소책자 인쇄 순서를 직접 비교하지 않습니다. 소책자 순서는 출력 엔진에서 별도로 검사합니다.

## 5. 지원 기기와 브라우저

최소 검사 대상:

| 기기 | 브라우저 | 주요 확인 |
| --- | --- | --- |
| Windows PC | Chrome, Edge | 전체 편집·파일·인쇄 |
| Chromebook | Chrome | 저사양 편집·키보드 |
| iPad | Safari | 터치 이동·파일 선택 |
| Android 태블릿 | Chrome | 터치 이동·화면 배치 |
| 일반 스마트폰 | Chrome, Safari | 간단 편집·책으로 보기 |

화면 너비 기준:

- 360px
- 768px
- 1024px
- 1440px 이상

접근성 확인:

- 키보드만으로 주요 기능 사용
- 포커스 테두리 표시
- 색상 외의 글자·아이콘 상태 표시
- 최소 44px 터치 영역
- 화면 확대 200%에서 기능 손실 없음
- 동작 줄이기 설정에서 불필요한 움직임 제거

## 6. 대량 페이지와 이미지

검사 책:

- 20페이지·이미지 10개
- 50페이지·이미지 30개
- 100페이지·이미지 60개
- 200페이지·이미지 100개

기록할 값:

- 첫 화면이 편집 가능해질 때까지 걸린 시간
- 페이지 이동에 걸린 시간
- 자동 저장 시간과 저장 크기
- 플립북을 열 때 걸린 시간
- 인쇄 미리보기를 만드는 시간
- 브라우저 메모리 사용량

초기 권장 목표:

- 50페이지 책은 기준 학교 PC에서 3초 안에 편집을 시작할 수 있어야 합니다.
- 페이지 선택 반응은 0.2초 안에 보여야 합니다.
- 자동 저장 중에도 글 입력과 드래그가 멈추지 않아야 합니다.
- 100페이지 이상에서는 보이지 않는 페이지와 이미지를 지연 로딩해야 합니다.

이미지는 원본과 화면용 파생 이미지를 구분해 검사합니다. data URL을 대량으로 localStorage에 저장하는 방식은 운영 저장 방식으로 사용하지 않습니다.

## 7. PDF 치수 검사

각 PDF는 브라우저 인쇄 화면뿐 아니라 외부 PDF 뷰어에서 확인합니다.

용지 규격:

| 용지 | 기준 크기 |
| --- | --- |
| A4 | 210×297mm |
| A3 | 297×420mm |
| ISO B4 | 250×353mm |
| JIS B4 | 257×364mm |

검사 항목:

- PDF 페이지 크기
- 세로·가로 방향
- 앞표지·본문·뒤표지 순서
- 양면 앞·뒤 순서
- 소책자 시트 배치
- 자동 빈 페이지
- 글꼴 포함과 한글 깨짐
- 이미지 해상도와 잘림
- bleed·안전 여백·gutter
- 프린터 보정값 적용 전후 좌표

코드가 계산한 PDF 좌표 목표 오차는 0.1mm 이하로 둡니다. 외부 뷰어의 자동 축소가 꺼진 상태에서 측정합니다.

## 8. 실물 양면 위치 검사

프린터별로 다음 정보를 기록합니다.

- 제조사와 모델명
- 드라이버 버전
- 급지함
- 용지 크기와 규격
- 종이 제품명·평량·실제 두께
- 긴 변·짧은 변 넘김
- PDF 뷰어
- 인쇄 배율
- 앞면 좌우·상하 오차
- 뒷면 좌우·상하 오차
- 회전 오차

한 설정에서 최소 3회 출력합니다.

초기 판정 기준:

| 실물 측정 결과 | 판정 |
| --- | --- |
| 앞뒤 중심 차이 1mm 이하 | 통과 |
| 1mm 초과 2mm 이하 | 주의·프로필 재조정 |
| 2mm 초과 | 실패 |
| 세 번의 출력 편차가 1mm 초과 | 프린터 급지 불안정으로 별도 기록 |

이 기준은 학교 프린터 실측 결과에 따라 조정할 수 있습니다.

## 9. 종이 두께와 책자 밀림

검사 조합:

- 약 0.10mm 일반지
- 약 0.13mm 중간 두께
- 약 0.18mm 두꺼운 종이
- 4쪽·12쪽·24쪽·40쪽 책자

측정 위치:

- 가장 바깥 종이의 재단선
- 가장 안쪽 종이의 재단선
- 접힌 뒤 각 페이지 내용 중심
- 글과 그림의 gutter 침범 여부

책자 밀림 보정 적용 전·후 값을 모두 기록합니다. 안쪽과 바깥쪽 페이지 내용 중심 차이의 초기 목표는 1.5mm 이하입니다.

## 10. 개인정보와 자산

- 학생 이름과 자산 URL을 콘솔 로그에 출력하지 않습니다.
- 토큰·비밀번호·Supabase 키를 브라우저와 로그에 노출하지 않습니다.
- 책 JSON에는 계정 이메일과 권한 정보를 넣지 않습니다.
- 이미지 삭제 전 해당 이미지를 사용하는 페이지와 저장본을 확인합니다.
- 학생 제출본이 참조하는 자산은 수정본 삭제와 함께 삭제하지 않습니다.
- 서버 저장 연결 후에는 RLS와 권한 없는 직접 URL 접근을 검사합니다.
