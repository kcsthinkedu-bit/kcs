# 책 편집기 사용자와 권한 계약

## 목적

책 편집기는 로그인 공급자와 직접 결합하지 않는다. KCSedutech 또는 퍼즐로가 확인한 사용자 정보를 공통 세션 형태로 전달하면, 편집기는 이 문서의 정책에 따라 기능을 보여준다.

인증 연동이 확정되기 전까지 실제 회원가입, 학생 초대, 서버 제출 기능은 켜지 않는다.

## 사용자 구분

| 내부 값 | 화면에서 사용할 이름 | 할 수 있는 일 |
| --- | --- | --- |
| `guest` | 로그인하지 않은 사용자 | 이 기기에서 책 만들기, 파일로 보관하기, 미리보기와 인쇄 |
| `member` | 일반 사용자 | 내 계정에 책 저장, 최종본 만들기 |
| `student` | 학생 | 배정된 책 편집, 내 작업 저장, 선생님께 제출 |
| `teacher` | 선생님 | 학생 초대, 학생 작업 확인, 제출본을 사본으로 수정, 돌려주기 |

화면에서는 가능한 한 `권한`, `리비전`, `에셋` 같은 개발 용어를 쓰지 않는다. 각각 `사용할 수 있는 기능`, `저장된 작업`, `그림 파일`로 표현한다.

## 공통 세션 입력

```js
{
  authenticated: true,
  role: "teacher",
  userId: "server-issued-user-id",
  academyId: "server-issued-academy-id",
  classIds: ["server-issued-class-id"],
  verifiedByServer: true
}
```

- `userId`, `academyId`, `classIds`는 서버가 발급한 식별자만 사용한다.
- 이름, 이메일, 전화번호는 책 문서 JSON에 저장하지 않는다.
- 브라우저가 임의로 만든 역할 값은 신뢰하지 않는다.
- 서버 확인이 없는 세션은 손님과 같은 범위에서만 동작한다.

## 저장본의 구분

| 화면 이름 | 만든 사람 | 원본 변경 여부 |
| --- | --- | --- |
| 작업 중 | 학생 또는 작성자 | 현재 작업을 이어서 편집 |
| 제출한 책 | 학생 | 제출 뒤에는 고정된 사본 |
| 선생님이 고친 책 | 선생님 | 학생 제출본을 바꾸지 않고 새 사본 생성 |
| 돌려받은 책 | 선생님 | 학생이 이어서 고칠 새 작업 생성 |
| 완성한 책 | 작성자 또는 선생님 | 인쇄·PDF 기준으로 고정 |

모든 사본은 `parentRevisionId`로 바로 이전 저장본을 가리킨다. 학생 제출본과 선생님 수정본을 같은 레코드에 덮어쓰지 않는다.

## 서버가 반드시 확인할 항목

1. 현재 사용자가 해당 책을 열 수 있는지
2. 선생님과 학생이 같은 수업 또는 초대 관계인지
3. 제출·수정·돌려주기 상태 전환이 허용되는지
4. 이미지 파일을 현재 책이 참조하는지
5. 저장 응답 뒤 다시 읽은 데이터가 같은 버전인지

화면에서 버튼을 숨기는 것은 편의를 위한 처리일 뿐 보안 검사가 아니다. 위 항목은 API에서 다시 확인한다.

## 인증 연동 전 동작

- 로컬 편집, JSON 내려받기·불러오기, 플립북 미리보기, 인쇄는 사용할 수 있다.
- 학생 초대, 계정 저장, 제출, 선생님 수정, 돌려주기는 `로그인 연결 후 사용할 수 있어요`로 안내한다.
- 로컬 저장본을 서버 저장 성공으로 표시하지 않는다.
- 인증 공급자 계약이 정해지기 전에는 `shared/book-access-policy.js`에 공급자별 코드를 넣지 않는다.

## 연동 재개 조건

1. 로그인 세션을 읽는 공식 방법
2. 일반 사용자·학생·선생님 역할의 서버 기준
3. 학생 초대와 수업 소속 데이터 구조
4. 책·저장본·이미지의 소유권 API
5. 저장 성공 뒤 readback을 확인할 API 계약

이 다섯 항목이 확정된 뒤 인증 어댑터와 서버 저장 UI를 연결한다.
