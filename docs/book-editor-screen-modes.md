# 책 편집기 사용 화면 계약

## 왜 권한과 화면을 나누는가

`학생 화면`을 고르는 것은 편집기를 쉽게 보이게 하는 선택이다. 사용자의 실제 학생 권한을 부여하는 동작이 아니다. 같은 원칙으로 `선생님 화면`을 골라도 다른 사람의 작업을 열 수 있는 권한은 생기지 않는다.

- 사용 화면: 브라우저에서 어떤 도구와 설명을 보여줄지 결정
- 사용자 권한: 로그인 서버가 어떤 책과 저장본에 접근할 수 있는지 결정

## 세 가지 사용 화면

| 화면 이름 | 목적 | 기본으로 보여줄 기능 |
| --- | --- | --- |
| 혼자 만들기 | 일반 사용자 개인 제작 | 편집, 파일 보관, 플립북, 인쇄 |
| 학생 화면 | 수업 중 간단한 제작 | 내 작업, 저장, 제출 준비, 플립북 |
| 선생님 화면 | 수업 준비와 피드백 | 수업용 원본, 학생별 작업, 선생님 수정본, 출력 설정 |

## 구현 규칙

1. 화면 모드는 URL의 `mode`와 현재 기기의 설정으로 기억한다.
2. 책 문서 JSON에는 화면 모드를 저장하지 않는다.
3. `data-student-only="true"`와 `data-teacher-only="true"`로 화면 전용 영역을 구분한다.
4. 서버 작업을 실행하기 전에는 반드시 `book-access-policy.js`로 확인하고 API에서도 다시 확인한다.
5. 로그인 연동 전에는 학생 초대와 온라인 제출을 사용할 수 있다고 표시하지 않는다.

## 쉬운 용어

- `mode` 대신 `사용 화면`
- `role` 대신 `회원 종류` 또는 문맥에 따라 `학생`, `선생님`
- `revision` 대신 `저장된 작업`
- `submit` 대신 `선생님께 제출하기`
- `return` 대신 `학생에게 돌려주기`
