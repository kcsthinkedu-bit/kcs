# KCS 공통 책 데이터 계약

## 목적

컬러링북, 그림책, 활동책이 같은 편집 기능을 재사용하면서도 책 종류별 화면과 출력 규칙을 다르게 적용하기 위한 공통 계약입니다.

이 계약에서 가장 중요한 원칙은 다음과 같습니다.

- 책 내용과 회원·학급 정보를 분리합니다.
- 페이지는 독자가 읽는 순서로 저장합니다.
- 양면·소책자 인쇄 순서는 PDF를 만들 때 계산합니다.
- 학생 작업, 학생 제출본, 선생님 수정본은 서로 덮어쓰지 않습니다.
- 원본 이미지와 화면용·출력용 파생 이미지를 구분합니다.
- 기존 `kcs-book-v1` JSON은 변환해서 불러오고 원본 파일은 변경하지 않습니다.

## 세 가지 경계

### 책 문서

`kcs-book-v2` JSON은 다른 사람에게 전달하거나 내려받을 수 있는 책 내용입니다.

- 책 종류와 제목
- 페이지와 페이지 순서
- 그림·글·도형
- 책 보기 설정
- 인쇄 기본 설정
- 사용한 이미지 자산 참조

회원 이름, 학생 이름, 학급, 권한, 이메일은 책 문서 안에 넣지 않습니다.

### 서버 소유권

소유권과 수업 연결은 `book_projects` 행에서 관리합니다.

- `owner_user_id`
- `academy_id`
- `class_group_id`
- `student_id`
- `feature_key`

인증 방식이 확정되기 전에는 이 필드의 연결 방식을 변경하지 않습니다.

### 저장본

저장본은 책 문서를 감싸는 별도 기록입니다.

| 내부 값 | 화면에 표시할 말 | 의미 |
| --- | --- | --- |
| `draft` | 작업 중 | 자동 저장되는 현재 작업 |
| `submission` | 학생 제출본 | 학생이 제출한 시점의 변경 불가 사본 |
| `teacher-edit` | 선생님 수정본 | 제출본에서 시작한 선생님 작업 |
| `returned` | 다시 고칠 책 | 선생님이 학생에게 돌려준 사본 |
| `final` | 최종본 | 출력 대상으로 확정한 사본 |

선생님이 학생 제출본을 열어 편집하면 `teacher-edit` 저장본을 새로 만듭니다. 학생 제출본 자체는 변경하지 않습니다.

## 책 종류와 편집 기능

책 종류는 별도 편집 프로그램이 아니라 공통 편집기에 적용되는 기본 설정입니다.

| 책 종류 | 화면 이름 | 기본 보기 | 기본 인쇄 |
| --- | --- | --- | --- |
| `coloringbook` | 컬러링북 | 한 페이지 | 단면 |
| `picturebook` | 그림책 | 양쪽 페이지 | 양면 |
| `storybook` | 이야기책 | 양쪽 페이지 | 양면 |
| `worksheet` | 활동책 | 한 페이지 | 단면 |

책 종류가 달라도 페이지는 그림, 글, 도형 요소를 공통으로 사용할 수 있습니다. 학생에게 보이는 도구만 `toolSetup.studentTools`로 줄일 수 있습니다.

## 페이지 계약

`pages` 배열은 항상 독자가 읽는 순서입니다. 배열 순서와 `order`는 같아야 합니다.

페이지 역할:

- `front-cover`: 앞표지
- `inside-front-cover`: 앞표지 안쪽
- `content`: 본문
- `blank`: 의도적으로 비운 페이지
- `inside-back-cover`: 뒤표지 안쪽
- `back-cover`: 뒤표지

왼쪽·오른쪽 위치는 저장하지 않고 읽는 순서, 읽기 방향, 표지 포함 여부로 계산합니다. 그래야 페이지를 이동해도 잘못된 좌우 값이 남지 않습니다.

## 요소 계약

모든 요소는 공통 위치 정보인 `frame`을 가집니다.

```json
{
  "x": 10,
  "y": 10,
  "width": 80,
  "height": 30,
  "rotation": 0
}
```

`x`, `y`, `width`, `height`는 페이지 크기에 대한 백분율 좌표입니다. 화면 크기와 출력 용지가 달라도 같은 배치를 유지하기 위한 기준입니다.

글 요소는 다음 공통 서식을 사용합니다.

- 글꼴
- 글자 크기
- 굵기
- 기울임
- 밑줄
- 글자색
- 정렬
- 줄 간격
- 글자 간격

그림 요소는 `assetId`로 원본 자산을 가리킵니다. 이전 JSON의 data URL은 변환 중 `source`에 임시로 보존하고, 서버 저장 시 `book_assets`로 분리합니다.

## 페이지 크기와 인쇄 용지

완성된 책의 페이지 크기와 프린터에 넣는 용지는 서로 다른 값입니다.

- `pageSetup.finishedSize`: 완성 책의 한 페이지 크기
- `printSetup.sheetSize`: 프린터에 넣는 A4·B4·A3 용지
- `printSetup.mode`: 단면·양면·소책자

B4는 ISO와 JIS 크기가 다르므로 `printSetup.sheetStandard`를 함께 저장합니다. 실제 기본값은 실물 출력 검증 후 확정합니다.

프린터 위치 보정값은 책에 직접 저장하지 않습니다. `calibrationProfileId`로 프린터·용지별 보정 프로필을 참조합니다.

## 이전 형식 변환

`upgradeLegacyProject()`는 기존 `kcs-book-v1`의 표지와 펼침을 다음처럼 변환합니다.

```text
기존 표지 → 앞표지 페이지
왼쪽 글 → 글 요소가 있는 본문 페이지
오른쪽 그림 → 그림 요소가 있는 본문 페이지
마지막 → 뒤표지 페이지
```

변환된 프로젝트에는 `migration.sourceFormat`과 변환 시각을 남깁니다. 이전 JSON 파일이나 서버 원본은 자동 삭제하거나 덮어쓰지 않습니다.

## 파일 위치

- 계약과 변환 함수: `shared/book-model.js`
- JSON Schema: `shared/book-project.schema.json`
- 현재 DB 후보: `docs/supabase-book-helper-schema.sql`

이 계약을 실제 서버 테이블에 적용하려면 인증·권한 계약, 운영 DB 백업, RLS 정책, 실데이터 변환 검증이 먼저 필요합니다.
